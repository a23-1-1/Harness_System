# DB Demo Studio — 产品文档

> 面向 AI Agent 的产品功能参考。Agent 在实现功能前应读此文档理解用户故事和交互模式。

---

## 产品定位

**DB Demo Studio** = AI 对话工作台 + 数据库课程演示生产流水线。

教师通过自然语言对话与 AI 协作，完成数据库课程知识点的**演示生成、可视化、模拟器搭建、讲解词打磨、测验出题和效果验证**。所有功能都通过对话触发、对话优化、对话反馈。

```
┌─ 对话列表 ───────────────────────────────────────────────┐

│                                                          │
│    B+树索引原理 (P2 模拟器)                               │

│                                                          │
│    事务隔离级别 (P2 事务演示)                              │

│                                                          │
│    SELECT 基础语法 (P0 即时)                               │
│    📁 草稿 | 未完成                                        │
│                                                          │

```

### 对话生命周期

```
创建对话 (标题自动生成/手动命名)
    │
    轮次 1: 用户输入知识点/案例/SQL → AI 生成演示初稿
    │       用户可: 反馈/修改/追问
    │
    轮次 N: 用户迭代精修 → AI 实时响应
    │       每轮对话产生一个"演示快照版本"
    │
    定稿: 用户满意 → 标记为"已定稿"
    │
    导出: 交互网页 / MP4 / Mermaid 代码 / 嵌入 LMS
    │
    存档: 对话历史完整保留 → 可回溯/可复用/可对比
```

### 对话状态流转

```
active ──→ draft ──→ finalized ──→ archived
  │          │           │
  │          │           └── 已定稿，可导出
  │          └── 草稿，未完成
  └── 正在对话中
```

## 消息模型

### 消息类型

| type | 显示 | 示例 |
|------|------|------|
| `text` | 普通文字消息 | "讲讲 JOIN 查询" |
| `sql` | 代码块 + 语法高亮 | `SELECT * FROM students JOIN courses ON ...` |
| `image` | 图片预览 | 上传的表结构截图 |
| `demo_snapshot` | 演示快照卡片 + 版本号 | [v3] JOIN 查询演示 |
| `tool_call` | 工具调用状态条 | "🔍 正在调用 sql_analyze..." |
| `quiz` | 答题卡片 | 选择题/判断题/简答 |
| `knowledge` | 知识点标签 | #JOIN #NestedLoop |

### 消息角色

| role | 样式 | 说明 |
|------|------|------|
| `user` | 右对齐，蓝色气泡 | 用户消息 |
| `assistant` | 左对齐，灰色气泡 | AI 回复 |
| `system` | 居中，灰色文字 | 系统通知（"对话已创建"） |
| `agent` | 左对齐，带进度条 | AI 内部执行轨迹 |

## P0 即时演示：6 阶段分步讲解

### 6 个阶段

| 阶段 | 显示名称 | 点击交互 |
|------|---------|---------|
| **lex** | 词法分析 | 点击关键字 → AI 解释每个关键字含义 |
| **parse** | 语法解析 | 点击表名 → AI 展示表结构 + 索引信息 |
| **optimize** | 查询优化 | 点击代价数值 → AI 对比其他扫描策略 |
| **plan** | 执行计划 | 点击代价数值 → AI 拆解代价构成 |
| **execute** | 执行过程 | 点击扫描行数 → AI 对比估计 vs 实际 |
| **result** | 结果分析 | 点击结果行 → AI 生成教学总结 |

### 对话示例

```
用户: 讲讲 JOIN 查询
AI:   好的！我来分析 JOIN 查询的执行过程。
      [调用 sql_analyze] 识别到 SELECT ... FROM students
      INNER JOIN courses ON ...
      [调用 explain_mysql] MySQL EXPLAIN 完成
      [调用 explain_postgres] PostgreSQL EXPLAIN 完成
      [生成演示] 6 步演示已就绪，我推荐用 P1 Mermaid 可视化展示。
      要现在预览吗？
```

## P2 专业模拟器

### SQL 分步执行模拟器

**触发**："模拟这个 SQL 一步步怎么执行"

**交互**：
- 用户逐步点击 → 每一步显示扫描的表、匹配的行、中间结果
- 对比 Nested Loop / Hash Join / Sort Merge 三种策略
- 实时显示代价估算和实际行数

### B+树模拟器

**触发**："演示 B+树插入 42 的过程"

**交互**：
- D3.js 动画：节点分裂、键值上推、根节点变化
- 支持插入/删除/查找三种操作
- 对话调整参数："插入 50 之后再加 60"

### 事务隔离级别模拟器

**触发**："演示 RR 级别下的幻读"

**交互**：
- 双会话并排展示（会话 A / 会话 B）
- 时间线滑块控制操作顺序
- 切换隔离级别（READ UNCOMMITTED → SERIALIZABLE）实时看到结果变化

## 测验系统

### 出题

**教师端对话**：
```
"给这个知识点出 3 道选择题" → AI 生成 3 道题
"太简单了，加难度" → AI 调整
"再加一道判断题" → AI 生成
```

### 学生答题

**界面**：嵌入式答题卡片，在演示步骤中穿插出现。

**答题流程**：
1. 题目出现在当前步骤下方
2. 学生选择/输入答案
3. ✅ 正确 → 显示解释 + 继续
4. ❌ 错误 → AI 对话式引导："你的思路是...不过考虑一下索引的作用？"

### 掌握度追踪

**教师端对话**：
```
"学生哪些知识点比较薄弱？" → AI 基于答题数据汇报
"下一步该讲什么？" → AI 根据掌握度推荐下一个知识点
```

## 课堂广播

### 教师端 → 学生端同步

```
教师端操作: player:seek → step:3
    ↓
FastAPI → Redis Pub/Sub "room:{convId}"
    ↓
Room 内所有学生 WebSocket 收到同步消息
    ↓
所有学生端跳转到 step:3，开始同步播放
```

### 学生端 AI 追问

学生在同步观看时可以**独立对话**：
```
学生: 为什么这一步选了 Nested Loop？
AI:   [苏格拉底式引导] 好问题！你能告诉我这两个表各有多少行吗？
学生: students 有 100 行，courses 有 20 行
AI:   没错！小表 courses 作为驱动表是为什么？
```

学生的对话不影响其他学生——每个学生有独立的 AI 对话上下文。
